# 当前工程选择的受控核验

日期：2026-10-01。目标是为当前求职工作流选择可靠、可解释、成本合理且便于维护的实现。
本次比较有明确范围，不宣称枚举所有架构或证明唯一最优。

## 保留的选择

| 选择 | 本轮依据 |
|---|---|
| LangGraph 受限流程 | 简单循环原型在 15 组配对测试中行为相同，节省的本机开销为毫秒量级，模型调用次数相同；保留显式节点、条件边和现有可审计流程 |
| 当前小语料默认全量上下文 | 当前语料 65 条、约 6,020 字符；全量不会因初次检索遗漏关键事实。此前 50 岗端到端比较的成本结果仍只对应其冻结版本，见 EVAL.md |
| 保留 BM25 / 向量 / 混合模式 | BM25 在本次目标检查中表现良好；检索可压缩初始上下文，但需要继续观察复杂 JD、语料扩展和模型补查开销 |
| Skill 与匹配 Agent 配合 | 单岗证据判断具有可重放执行路径；官方来源、完整范围、选岗规则、用户授权和 ATS 操作继续由各自 Skill 处理 |
| 确定性校验、事务与岗位级恢复 | 保留正式匹配校验器、预览令牌、版本校验、写后读回和冻结批次恢复；它们分别约束不同的错误与副作用 |

## 检索对比：同一语料与同一查询

从当前证据中核对 12 个检索目标，在运行前固定查询、关键证据 ID 与语料快照。
每个查询取 top-5，随后和生产路径一样附加所有经历边界；全量模式提供全部语料。
目标包括接口开发、LLM 容错、IRT、NuRec、工业视觉、Agent、检索、MCP、恢复、学历、专利分工和数据库经历边界。

| 方式 | 指定目标可见 | 每查询提供的证据字符数中位数 | 本机搜索耗时中位数 | 固定 12 条要求的初始判断输入 UTF-8 字节数 |
|---|---:|---:|---:|---:|
| 全量 | 12/12 | 5,955 | <0.001 ms | 23,753 |
| BM25 | 12/12 | 2,118 | 0.260 ms | 21,035 |
| 向量 | 11/12 | 2,041.5 | 2.284 ms | 19,422 |
| RRF 混合 | 11/12 | 2,054.5 | 2.663 ms | 20,189 |

向量和混合模式在 API 查询中返回了相关技能或边界，但初次 top-5 未包含指定的实习项目证据。
这不等于最终判断必然错误：模型可以补查，其他条目也可能具有支持作用。

**范围与限制：**这是助手核对的检索目标覆盖检查，不是独立人工匹配金标。检索部分没有调用 LLM；字符和字节数不是 token 或费用。
同一 JD 的多条要求会产生证据并集，因此不能把单查询压缩比例当作整轮成本节省。
本轮没有把补查后的最终判断质量或调用量作为检索胜负依据，也没有据此调参后再用同一组目标宣称泛化提升。

## 执行器对比：LangGraph 与简单循环

循环原型调用同一套准备、抽取、检索、判断、工具、决策、校验和纠错方法。
使用相同的预制模型响应与正式校验器，覆盖直接通过、补查后纠错、纠错耗尽三种路径，各重复 5 次；配对运行顺序交替。

| 执行器 | 运行数 | 构建耗时中位数 | 执行耗时中位数 |
|---|---:|---:|---:|
| LangGraph | 15 | 5.440 ms | 41.420 ms |
| 简单循环原型 | 15 | 0.418 ms | 30.840 ms |

15/15 配对的执行状态、机械通过状态、首次通过、补查次数、纠错次数、决策和模型逻辑调用次数一致。
执行时间包含本地文件和校验流程，未运行最终报告发布步骤；构建时间包括对应检索器初始化。
预制响应不包含网络延迟，也不能用来比较语义准确率。简单循环原型没有完整生产入口和维护支持，不作为新增公共运行模式。

当前没有证据表明替换执行器能减少真实模型调用或改善判断，因此保留 LangGraph。

## 本轮实际修复

### 限制引用到实际展示的证据

原实现只检查引用 ID 是否存在于完整语料。检索模式下，模型可能猜中库中存在但未展示的 ID，正式校验仍接受。

当前流程记录初始证据与工具返回的 ID；只有已经展示的证据可以进入候选来源引用集合。
未展示的 ID 保留在原始判断中，由正式校验器拒绝并进入既有纠错流程。
工具补查后可正常引用新证据，纠错也不能猜用未展示条目。默认全量模式仍提供全部证据。

### 并发缓存写入

原向量缓存使用同一个固定临时文件名。两名写入者同时构建相同索引时，可复现一名替换文件后另一名收到 FileNotFoundError。
现在每个写入者使用独立临时文件，完整写入并关闭后原子替换缓存，最后清理自身临时文件。

### 完整读取已经确认的事实

学术成果抽取新增“实际分工说明”，同时保留正式署名顺序与来源中的“本人说明”，避免仅提供排名而遗漏实际分工。
当前工作区另通过既有 extra-evidence.md 入口承接母表尚未设置独立条目的 CareerWorkbench 项目细节；原始来源与限制保留在私有说明中。
这份补充文件是本机派生资料，不随代码公开；其他使用者需提供自己的证据。
