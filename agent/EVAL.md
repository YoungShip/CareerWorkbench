# 50 岗位端到端配置比较

范围：只比较“单岗 JD 与候选人证据匹配”子模块的四种配置。full 指提供全部已抽取候选人证据；不等于公司全量调研，也不是整个求职工作流的整体效果验收。该比较用于选择当前小语料的运行方式、暴露工程失败和估计开销，不能证明选岗判断的语义准确率。

日期：2026-09-29。固定评测代码版本：44d1c29d20335e3febe5ad3db95e2469cc33fa41。
代码字节哈希：89d82e58b913981fb9ae627e520083dd09626e34abbee190165ee027efdcc2e7。四组样本与语料哈希一致，原始结果保留在私有目录。

## 设置

- 同一批 50 份历史 JD、55 块候选人证据；各配置每岗运行一次，共 200 次。
- 接口请求的模型 ID 为 global:deepseek-v4.1-flash，经用户提供的本地 CPA；模型 ID 不视为对底层路由身份的独立认证。
- 最多两次补查、两轮业务纠错；温度 0，输出上限 8192，4 个并发任务；每岗使用独立模型会话。
- 每组独立拆解要求，因此属于端到端配置比较，不是冻结同一要求后的严格检索因果实验。没有重复试验或置信区间。
- 全量上下文只发送一份完整证据；检索模式共享去重的证据正文，并始终附带同一组经历边界。

首次业务校验可能发生在格式重试之后，不等于第一次 API 调用就产生有效答案。校验只覆盖结构、引文存在性、支持关系/结论组合及汇总一致性，不能证明语义判断正确。

关键词组的一次回答超过输出上限，保留为失败，不生成可用决策。全量与混合各有一岗经过业务纠错后通过。所有失败均留在分母，未用挑选成功重跑替换结果。

耗时是本机本轮、包含请求和校验的单岗观测，不包含一次性模型下载/索引初始化。tokens 采用网关返回用量；未配置价格，费用未知，不能报为零费用。

## 工程选择

当前小型证据库以全量上下文作为 CLI 默认入口。相对混合检索，本轮输入 tokens 少约 41.5%，输出 tokens 少约 16.4%，耗时中位数少约 20.9%，两者最终机械校验均通过 50/50。
三种检索方式仍可显式选择，适用于后续语料扩展和继续实验。本轮不证明全量上下文的语义质量更高，也不能把差异全部归因于向量检索：工具补查次数和模型输出也不同。

## 标签与语义限制

- 50 条用户标签为初步投递意向（39 投、11 不投），用户说明主要按 AI 相关兴趣与关键词判断。它们不是能力匹配金标，也不是录用结果。
- 标注表中 25 条要点使用省略号；全文页与已保存的清洗快照一致，但不等于本轮重新核实了所有官网原文及开放状态。
- 全量与混合的最终状态有 8/50 不同；全量与关键词有 6/50 不同；全量与向量有 11/50 不同。没有独立语义金标，不能仅凭这些状态判谁更准确。
- pending 表示证据或条件待确认，不等于不值得尝试投递；城市、额度、志愿、开放状态等仍由既有研究流程和本人决定。

## 后续修正与复现边界

本轮固定版本比较完成后，判定节点补充了岗位标题/公司/城市背景，并明确校招在读学历需结合岗位明确届别与预计毕业时间理解；未明确届别时保持待确认。以上表格仍对应 44d1c29，不能称为后续所有改动版本的重新全量测试。
未来生成的标注表说明也已改为“投递意向”，要求核对全文并提供统一选项含义；原已填写表没有覆盖。

补传背景后的三个定向真实回归均通过结构校验：明确 2027 届且毕业窗口相符的硕士要求被判满足；博士硬条件仍判不满足；没有明确届别的快照继续保留学历待确认。这个结果不替代对全部样本语义正确性的人工验证。

## 夜间工程 v1 的定向验收（2026-09-29）

以下是后续版本的独立检查，没有改写上面的 200 次历史结果，也未再跑四组全量比较：

- 输入完整性：保留招聘上下文与链接要求、原文/转换哈希与源行映射；精确公司主体与绑定来源才关联岗位，不按相似 JD 或公司前缀合并。新池使用独立目录，旧标签不迁移。
- 证据抽取：不再近似去重，保留在读/日期暂用说明和全部经历边界。当前本地语料为 59 块，与历史比较的 55 块不同。
- 公开合成案例初轮 9/9 指定断言通过；随后为“单个项目未完成不能推全体经历否定”增加 1 个案例，单独调用 1/1 通过。两轮实现不同，不能称为最终版本同批 10/10 全量复测。
- 真实来源初轮出现一次提取输出截断，保留为失败；博士案例的检查器因同一 JD 行包含学历与能力而误把两条一起判分，已增加要求文字定位，没有删除旧失败报告。人工审阅还发现把局部项目未完成推成全局否定的问题。
- 修复后两份真实快照的学历/证据范围断言 2/2 通过；三岗演示审阅又发现复合要求“部分有证据却整条满足”，因此增加 unverified_aspects 和结构一致性约束。
- 最后一轮同公司三岗，指定学历冲突、量产缺证据、复合能力缺口、口头讲解能力未知、课程不能证明精通等断言 **3/3 通过**，并生成只读公司对照。最后运行的源码内容指纹为 4234d36e59875c7a8bc4d410ad21366aad3bce3f2c00d3591f4aab8c2e161235。

真实案例来源标为 assistant_reviewed：本助手核对指定 JD 片段和母表事实，未取得逐条用户复核，未重新访问官网，不是完整能力金标。复合要求仍可能被模型错误拆分或误认为无缺口，机械约束不能解决所有语义问题。

## 日常 Skill 接入联调（2026-09-29）

新增 research 入口，把当前官方目录、完整 JD 与现行规则交给 Agent，输出公司 matching v2，再交回 campus-recruitment 做来源、规则和语义审阅。Skill 源与本机安装副本同步，CI 使用包含适配器规范的固定技能版本。

本次只读联调从一家公司的当前公开校招列表抓取 9 页，目录声明总数与唯一 ID 均为 177；仅对本次指定的 2 个岗位运行匹配，其余 175 岗明确标为本次范围外。两个岗位均完成匹配与机械校验。没有把“目录抓完”称为“全部岗位已匹配”，没有自动补 human_attested 或选中岗位，因此全量比较/登记许可仍受原检查约束。

当前 API 正文与历史快照存在差异，不能确定是官网更新还是旧提取遗漏；本次使用新快照，历史评测与标签保持原样。Skill 审阅还把一处标题“可实习”与候选人届别要求分开，保留原输出、修正依据和新一版正式校验产物；未触发追加模型调用。

该联调证明官方快照→适配器→模型→公司记录→原校验器→Skill复核的读取与交回流程可运行。它没有覆盖账号登录、用户选岗、真实主表登记或最终网申提交，也没有得出总体语义准确率。隔离测试另覆盖完整/部分范围、身份错配、快照改动、观察引文不实、失败岗位保留和选岗授权边界。
