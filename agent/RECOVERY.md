# 批次中断与恢复

适用入口：eval-run、research、semantic-check。旧版没有 checkpoint.json 的历史运行保持原样，不自动迁移或改写。

## 使用

新运行开始时会打印目录。查看状态不需要模型 Key：

    uv run jobmatch run-status --run-dir "<运行目录>"

恢复尚未完成的岗位：

    uv run jobmatch resume --run-dir "<运行目录>"

已完成但失败的岗位默认保留；明确要重试时：

    uv run jobmatch resume --run-dir "<运行目录>" --retry-failed

语义断言失败但机械校验通过的案例不会因此反复抽样。修改实现后创建新运行，用同一冻结案例对照，保留原失败。

## 恢复规则

- 按岗位恢复。已封存岗位先验证文件哈希，再直接复用；未完成岗位在新 attempt 目录从头执行。
- 不从半截模型回答或某个图节点继续。请求已返回但检查点尚未提交时发生崩溃，该岗位可能重新调用模型；不承诺恰好调用一次。
- 当前批次的JD、候选事实、规则、评测集保持冻结。恢复不自动读取最新母表，也不把旧来源处理成今天重新获取的资料。选岗前仍须核对现行规则和官网。
- 代码、Python/依赖版本、模型配置、校验器及输入必须一致。变化后另开运行，不能混合比较。API Key可按原provider更新，密钥不保存进检查点。
- 恢复使用原运行目录；移动目录后绝对报告引用可能失效，会拒绝恢复。已归档产物仍可阅读。
- OS文件锁防止两个进程同时恢复；进程退出后由操作系统释放，不用超时强行抢锁。
- 并发中断会取消排队任务，并阻止后续模型调用/重试。在途请求可能等到本次响应或超时，不能保证服务端没有执行或计费。
- 报告生成中断不会重跑已封存模型任务；重新生成新的报告版本，旧目录和失败产物保留。

## 文件与指标

manifest.json、samples.json/cases.json、research-request.json、corpus.json等按入口冻结；checkpoint.json原子写入，保存输入契约、每岗状态、尝试和工件哈希。

单岗产物在 jobs/job-NNN/attempt-NNN/。文件被修改或丢失时停止复用，不能手工删掉失败再声称首次通过。

results.jsonl和当前报告指向最新有效结果，历史尝试及编号报告保留。已封存尝试的调用量、token和耗时累加；first_passed保留首个尝试的记录。中断或API没有用量回执时 usage_complete=false，已知token只作部分记录，总费用为null。

run-status只读检查点摘要，不代替完整文件核验。恢复时执行文件检查。语义检查与机械校验分别报告；检查点中的作业完成不表示语义断言通过。

eval-report会核对冻结样本数量和检查点；批次尚未完成时拒绝生成完整成绩，避免只拿已完成的成功样本计算通过率。
