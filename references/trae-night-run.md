# Trae 接入与夜间试运行

2026-09-13 用户同意在本机 Trae 使用同一套求职系统；首次验收研究一家，通过后首晚最多三家。此文件是执行器适配，不新增投递授权，也不创建定时任务。

## 共用文件与工具

在 Trae 打开整个 D:/AppData/Documents/resume。项目规则 .trae/rules/career-workbench.md 负责路由；三个 .trae/skills/ 子目录已改为 Windows 目录联接，直接访问 D:/AppData/Documents/resume/.agents/skills/ 的同一份完整技能和经验，不再保留短入口副本。相对资源路径随整个目录共享。不复制另一套投递表，不在新 worktree 假定存在个人 CSV；客户端刷新后的联接识别仍需实测。

先运行 `node D:/AppData/Documents/resume/CareerWorkbench/scripts/trae-preflight.js`。现有 Node 和 Python 可以由任意本机会话调用，无需启动 Codex；Python 默认路径仍位于本机 Codex runtime 缓存，缓存删除将导致依赖缺失。可在当前终端通过 JOBHUNT_PYTHON 指定其他已安装 Python，校验脚本仍固定为原可信技能文件，不允许研究计划选择另一个校验器。

预检仅检查文件、解释器、主表校验和发现快照，不验证 Trae 的工具授权。另须实际完成一次搜索、一次官方网页打开和动态列表读取，记录工具名、URL、结果及时间。当前工具缺失时保留待验证项，不假设 Codex 的 cua、web 或定时工具可在 Trae 调用。公开网页/API研究沿用技能规则；不要为通过验收读取认证文件或导出 token。OfferNotes 只在同步任务中按原技能验证已登录页面和所需执行能力；本轮研究不为测试制造线上变更。

## 单公司验收入口

研究登记不能豁免：池内公司用 research.complete；确有研究先于入池的公司用新公司发现协议的 research.register 显式补登记，保留来源、身份、材料校验和回执。正常新发现先入池再研究。已登记的公司不得重复 register；修复验收可复用已有成果，通过固定ID complete 验证，无需重复全量抓取。没有实际研究登记的 run.finish 不能算研究链路验收通过。

收到“执行单公司验收”后：

1. 读取 AGENTS.md、本文件、campus-recruitment 原技能及其新公司发现协议。执行预检和上述真实工具检查。预检失败先记录具体阻塞，不能开始主数据写入。
2. 读取最新档案、主表、认领和 discovery snapshot。已有 active_run_id 时确认归属，不能抢占或清除另一执行器的运行。Codex 和 Trae 不同时维护这些研究文件。
3. 选择一家未研究、未占用且符合最新方向的公司，完整执行认领、全量目录、范围内完整 JD、matching、verify、报告、索引及 research.complete；不重复研究中兴等已完成公司来凑验收。
4. 每个来源或公司处理后通过发现 CLI 保存断点。按 snapshot → preview → apply → snapshot 写入，完成后 run.finish、run-export。一次只研究一家，执行结束不自行转为长期循环。
5. 将报告存到 data/private/trae-runs/<本次唯一ID>/acceptance.md，列出实际读取的技能路径、工具检查、研究文件、验证计数、run_id、主表是否变化、剩余阻塞。只能在真实工具检查和完整研究均通过时写“单公司验收通过”。没有浏览器能力即使公共 API 研究完成也不能宣称浏览器验收通过。

## 首晚入口：用户启动后执行

先核对单公司验收结果。用户发出“开始首晚试运行”才进入本段；只准备文件或白天单公司验收不启动夜间任务。

- 首晚最多尝试研究三家公司，成功与阻塞都占尝试数；每个 discovery run 最多一家，本夜最多三个 run，仍遵守每轮最多10条新线索的代码限制。不能反复开 run 绕过本夜上限。
- 启动时在 data/private/trae-runs/<本夜ID>/night-session.json 保存 started_at、明确的 stop_at（下一个当地07:00）、max_attempts:3、已尝试公司、run_id 和状态。它是执行预算清单；公司线索和研究状态仍以 discovery 存储为准。恢复继续同一清单，不能重置预算。进程结束后不会靠这个文件自行唤醒。
- 每次开始一家前记录尝试并检查时间；来源操作之间检查时间。达到07:00或三家上限就保存断点并结束，未完整验证的研究保留未完成，不强行写 researched。07:00是会话检查边界，不是可强制中断挂起工具的系统定时器。
- 同一来源连续失败两次换入口；该公司仍无法完成则保存证据与阻塞、结束该轮并转下一家。额度不足、全局网络/工具失败或需人工登录时保存后停止，不无限重试。
- 每完成一家保存回执和更新 morning-report.md，最后汇总已验证推荐、未完成范围、阻塞和下一步。完整研究校验标准不因无人值守降低。未经用户选定不登记待投，不填写、上传、提交或对外发消息。
- 此方案由持续可用的 Trae 会话执行，不是后台守护进程。模型结束、权限弹窗、应用退出、电脑休眠或断网可能使其停止；恢复后人工发“按上次断点继续”，先核对归属和预算。未验证连续运行前不称整夜稳定。
