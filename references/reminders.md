# 提醒：判定、送达与只读模式

保留原有三个 Windows 任务及参数，本轮不重新注册、不新增对外通道。

- 默认 `remind.js` 和 `--json` 只读，不写运行日志；`--strict` 非零退出码表示有过期事项，不代表已发送。
- 与看板共用时间口径。“无截止/未知”不从邀请日期补出截止；固定安排保留安排含义，估算截止明确标注。
- 只有日期时按日末提供提醒参考，不当作官方精确时刻。保留 ISO 时区，不再次偏移当前时间。
- 阈值按精确毫秒判断：2小时优先于24小时。完成事项不提醒；过期且有下一步动作才进入单独补救提醒，超过30天不循环发送。
- 按事件身份、安排时间、阈值、通道去重；改期重新提醒。微信和桌面分别记录成功，失败通道仍可重试。
- 只在微信服务端成功回执或本机通知API成功返回后记入 delivered；这不证明人已阅读。
- 服务超时但实际接收、或发送后落盘前进程崩溃时仍可能重复，不能承诺严格 exactly-once。
- 新状态版本为2。旧 fired 写在发送之前，不能当作送达证据；新版首次正常运行可能补提醒当前仍有效的事项。本轮不手工伪造回执。
- 日常、登录和门槛发送共用进程锁，额度串行检查；活进程占锁时不重复发送。
- 真实额度记录或新版送达状态损坏时明确报错，不静默重置成零。按正常维护程序核对后恢复。
- `--dry-run` 不读密钥、不发送、不写额度、送达或运行日志。
- `--due --json` 是不考虑历史送达的候选预览，不是发送结果；需要按当前送达状态预览使用 `--due --dry-run`。

离线测试：`node --test scripts/reminder.test.js`。使用虚构数据和模拟发送器，不触发真实微信或 Toast。
本轮未重跑模型、未发送真实通知、未修改任务注册或主表。
