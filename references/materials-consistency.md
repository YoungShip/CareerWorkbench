# 简历与资料链路一致性

个人事实以工作区 `lapis-cv/秋招/网申档案.json` 为唯一维护母表；选岗规则与经历边界来自 `求职档案.md`。
简历是展示版本，网申文本和工作流索引是生成视图，匹配证据是白名单抽取结果。

## 修改一项经历时

1. 在母表建立或更新结构化记录；项目使用稳定 `id`，包含名称、角色、简介、职责、成果与边界。月份、精确日期和团队人数分别按实际已知状态填写，未知值不编造。
2. 项目声明 `网申文本组`、`适用版本` 和必要的 `简历标题别名`。简历可以简写标题，别名需显式对应同一项目，不按相似名称猜身份。
3. 更新对应字数版本后运行 `lapis-cv/scripts/generate_application_materials.py`。它生成 A/C 网申文本、资料总览，并按声明同步兼容描述和四份私有工作流视图。
4. 在 Agent 环境运行 `jobmatch check-materials`，再按需运行 `jobmatch corpus`。

简历正文和排版仍按用户指定由简历助手维护。把新项目写入 PDF 或自我介绍，不能替代母表结构化项目记录。

## 自动核查的内容

- 简历项目标题必须映射到母表中唯一项目；新增、遗漏、重复或未声明别名会报错。
- 项目分栏描述必须与声明的可复制文本同步；字数、上限与统计一致。
- 当前附件存在，文件大小及已有哈希记录有效；停用版本不进入新申请索引。
- 标准 A/C 的 PDF 原始文字与 Markdown 相符，仍为一页，不以 Unicode 归一化掩盖部首字符。
- 网申生成清单绑定母表字节哈希和输出文件哈希。
- 四份工作流视图绑定母表及现行规则哈希；不另存一套过时的回答或筛选阈值。

`jobmatch doctor` 和客户端只读预检会显示检查结果。实际匹配入口也会先检查，失败时在模型启动前停止，提示资料同步错误，不把错误解释成岗位不匹配。

## 已有匹配结果

使用 `jobmatch check-materials --matching-file <matching.json或含corpus.json的运行目录>` 核对旧结果的冻结证据版本。
`current` 表示与当前白名单证据相同；`stale` 表示事实已变，需按当前事实复核；`unknown` 表示不能直接比较，应人工核对。
历史结果、原始失败、已提交材料和投递事实保留，不批量改写。批次恢复继续遵守原代码/环境/输入冻结契约。

## 范围

这些检查防止结构化经历遗漏、资料未生成、旧文件混用和陈旧视图等确定性问题。
项目真实程度、语义匹配、个人熟练度、官网开放状态与实际提交仍遵循来源核实、Skill 复核和用户授权。
历史公司材料及已注明历史快照的文档不作为当前材料选择入口，也不因字面出现旧版本名而改写。
