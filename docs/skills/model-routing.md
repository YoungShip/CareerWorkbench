# Optional model routing

模型只是执行器，不能替代档案、官方来源、事务校验或页面读回。

在当前工作流中，可以按任务形态分工：

| 阶段 | 推荐角色 | 适合处理 |
|---|---|---|
| 公司研究、全量目录核对、JD 匹配、志愿排序 | 长上下文/推理模型，例如 `deepseek-v4.1-flash` | 多岗位比较、规则冲突、证据与缺口对账 |
| 网申页面填写、中文控件操作、字段读回 | 执行稳定/中文交互模型，例如 `fw/glm-5.3-flash` | 表单控件、上传解析后的修正、逐字段审计 |
| 提交前和同步后的复核 | 长上下文/推理模型 | 检查状态、ID、证据、阶段冲突和是否越过经历边界 |

这只是工作流分工建议，不是两个模型的官方 benchmark 结论。若页面上下文或工具会丢失，应优先保持同一会话连续完成当前阶段，而不是频繁切换模型。
