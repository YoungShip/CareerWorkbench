# Site knowledge base

本文件只记录可复用的站点差异，不记录候选人值、岗位 ID、真实申请日期、账号信息或材料原文。租户/批次/账号限定观察应留在本地私有覆盖层，不直接进入本文件。私有观察推荐使用 `knowledge_status: candidate|verified|historical`、`last_verified: YYYY-MM-DD`、`stale_after_days: N`；只有 fresh + verified 可直接作为操作提示，其他状态必须现场复核。公共条目应是去除个人信息后、跨独立站点重复验证的控件级规律；改版或反例出现时降级为待复核。

## Feishu-style custom form

- **入口特征**：职位详情通常含数字岗位 ID，申请页使用自定义表单组件。
- **上传**：常见 `input[type=file]`，上传后提供解析或覆盖选项。
- **字段**：基本信息、教育、实习、项目、城市和岗位专属问题。
- **坑位**：解析后检查教育起止、项目日期/角色/链接、描述中的标题残留，以及邮箱/手机是否被清空。
- **后续岗位**：资料复用需每个站点分别验证；重点检查新增问题和意向城市。

## Feishu ATS-X 控件候选模式（需现场验证）

- 通过 `atsx-` 类名、表单标签和 `data-cy` 辅助识别控件；选择器只作候选，必须先核对当前字段与重复区块。
- 异步表单以字段实际出现和可交互为准；不要把暂未渲染误认为额度已满，也不要固定等待后宣称完成。
- 自定义下拉可能使用展示文本而非 value；日期需要辨别年份/月、开始/结束及控件精度。输入后必须逐项读回。
- React 等受控输入需使用当前运行工具支持的交互路径；写入事件无报错不等于已保存。
- 必须检查推荐方式、推荐码、附件和岗位特定问题；不继承另一账号或另一岗位的授权。
- 后续岗位可能复用材料，但复用内容和完整性须每次核验，不能只核对城市或推荐码。
- 额度、志愿流转、可修改性和实际保存规则属于公司/门户/批次/账号，不属于 ATS 家族共性。未查到额度保持未知，实际申请仍逐岗遵守用户授权。
- 提交成功按对应岗位身份核对成功页与应聘记录；总条数或残留提交按钮均不能单独证明某岗提交成功。
- 带公司、日期、账号范围的观察由本地私有覆盖层保存；通用规则不得宣称其他租户必然相同。

## Moka/SugarDesign

- **入口特征**：`app.mokahr.com/campus-recruitment/...` 或同类组织路径；字段容器常带 `apply-field`/`apply-block`。
- **控件**：展示值可能在 span 中；自定义输入需要真实输入事件；年/月下拉可能倒序。
- **已知坑位**：出生日期日历、籍贯 tag-input、内层滚动、React 按钮以及未提交岗位之间的复用行为都要逐页验证。
- **审计重点**：解析后的学校/专业/学历、教育顺序、实习和项目区块、附件名。

## Zhiye/Phoenix

- **入口特征**：`<org>.zhiye.com` 或同类北森路径，流程通常分基本信息、履历、附件、预览。
- **控件**：原生 select 与自定义弹窗并存，日期格式以当前页面为准。
- **已知坑位**：异步脚本可能清空手机号/邮箱；弹窗逐条添加后必须逐条读回；真实性声明与验证码不能由自动流程猜测完成。

## Company-built form

先通过页面标签和 DOM 建立字段映射。对于 Ant Design 或其他通用组件，复用控件级方法即可，不复制另一家公司特有的选择器。任何新发现按“观察→验证→增量记录”落盘。
