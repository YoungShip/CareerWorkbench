# Online sync knowledge base

本文件只保留可复用的服务与浏览器经验，不保存任何候选人的记录、线上 ID、提交日期、账号信息或认证数据。服务改版后按“重新验证→标记范围→再推广”的顺序更新。

## Private record defaults

某些在线进度服务的新记录会把“私有可见”编码成非直觉的数值。OfferNotes 适配器的已验证经验是：新建时使用当前服务确认过的私有值（历史实现使用 `publish_delay=100000`），不要把 `-1` 或 UI 默认值直接当作私有值。写后必须读取详情确认可见性；若服务改版，先重新验证再沿用。

## Legacy note length

在线备注可能有约 2000 字符限制，而且超限时服务端可能返回空的成功响应。重试前完整读取旧备注，去掉完全重复的历史段和空分隔线，保留所有唯一内容、人工备注和完整链接；不要盲目截断、清空或删除人工内容。写后以读回值判断成功。

## Authenticated browser and CDP

- 页面标题或端口可用不等于已登录；先做无副作用登录探测，只返回布尔值/非敏感键名。
- 需要 CDP 时使用专用、非默认、可持久化 profile；不要对用户真实 Chrome `User Data/Default` 启动 remote debugging，也不要复制真实 profile 以“继承”登录态。
- 运行顺序为：启动专用实例 → 探测登录 → dry-run → 执行 → 独立读回 → ack → 通过 `Browser.close` 收尾。
- 同步脚本在页面函数闭包内执行；认证对象不返回到 shell、日志或文件。
- CDP 仅限在线进度同步和只读诊断，不用于网申填表或最终投递。

## Independent browser profile trap

独立的浏览器自动化 profile 没有用户日常会话的登录态，可能返回 403、空 localStorage 或“登录失效”。这不能证明用户账号失效，也不能通过反复新建实例猜测登录。改用已登录的会话浏览器；若任务确实是允许的在线同步，再使用专用、非默认、已验证登录的 profile。

## Scoped sync

payload 只包含本轮授权和已核实的 entries，但 identity index 应保留所有已绑定岗位。这样批量分割不会把缺席本批的岗位误认成新岗位。同步结果逐条记录 action/error；一条失败不能被整批成功状态掩盖。

## Managed block integrity

使用岗位 ID + 内容 hash 的管理区。判断管理区存在、是否被人工改动时必须读取备注全文；列表工具的 head/preview 可能截断管理区所在的尾部。标记缺失、重复、冲突或 hash 不匹配时停止该条，保留原文并请求核实。

## Stage text versus stage state

阶段的结构化 status 是权威字段，note text 只是辅助文字。可以统一文字约定，但不能用文字覆盖结构化待办/完成/结果状态。同步前检查线上是否已有更后续阶段或明确结果。

## Virtualized progress tables

在线进度表可能是虚拟滚动且不按创建时间排序，新记录不一定出现在首尾。UI 核对优先用公司/城市/部门搜索；接口读回才是写入验证的权威来源。不要因为滚动到底没有 DOM 行就判断记录不存在。

## Delete boundary

常规 reconcile 只创建和更新，不包含删除。删除线上记录仅在用户明确要求时进行：先 GET 详情确认当前用户和管理区 job ID，再逐个删除关联阶段，删除记录后读回 404/总数变化。任何归属不匹配都应中止。
